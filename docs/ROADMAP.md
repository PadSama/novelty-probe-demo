> 用途：让研究者随时掌握全貌。阶段内每完成一项任务就更新"状态"列并推送到工作分支；每个阶段结束随 PR 合入 `main`。

## 1. 目标与边界

**目标**（研究者 Step 66 的要求）：迭代承重层工具本身的**准确性、稳定性、适配性**，为后续实用化做准备。教程 v1、v2 的结果"是啥就是啥"，不再为它们调参。

**不做**：为提高某一轮结果而调整检索词或参数；引入第三方依赖；机器学习式筛选；判断新颖性（PROJECT.md 规则 1）。

**设计原则**（研究者 2026-11-03 提出）：**减少中间环节的人工参与**。文献探查只是整个研究的起点，脚本能自动完成、自动判断的就不留给研究者：不设人工复核表；作者随检索取得；RIS、运行清单与检索报告在合并时自动生成。需要研究者判断的只留研究范围、检索词、标注标准这类真正属于研究设计的问题。

**每个阶段的完成标准**：

1. 离线测试在本地 Python 3.9 与 3.13 全部通过，GitHub Actions 的 15 个组合（3.9–3.13 × Ubuntu / Windows / macOS）全绿；
2. 已有产出不变：`merge.py --legacy` 逐字节复现 v1、v2；录制件回放的记录与改造前相同；
3. RUN_LOG 记一步，HOWTO / HANDOFF / AGENTS / README 同步；
4. 助手开 PR 并跟进 CI 与审阅，研究者审阅合并；研究者确认后进入下一阶段。

**本轮的发现**：

- **证据检查漏看第二个标识符**：同一篇同时有 DOI 与 arXiv ID 时，作者比对只看排在最前的标识符，与另一个标识符下的作者一致也会误报；编写测试时发现，已修正。
- **作者证据的边界**：作者名只用汉字等非拉丁字母书写时没有可比的词，原实现会把"无法比较"当成"没有共同的名字"而拆开同一篇（R7）；改为这种情况下作者不作证据。
- **作者规则尚未在真实数据上起作用**：v1、v2、v1b、v2b 都是阶段 4 之前检索的，没有作者，只用到 D1–D4 与 R2、R3、R6；D5、R7 由测试覆盖，下一轮真实检索时才会用上。教程数据中最大的合并组是 2 个标识符分组，R8 的上限 6 没有触发。

**阶段 4 验收**：

1. 没有作者的旧数据（v1、v2、v1b、v2b）合并结果除新增字段外不变；`--legacy` 照常逐字节复现；
2. 每个合并决定都能追溯到规则编号；打乱输入顺序重跑，合并结果相同；
3. 研究者不用多做一步：检索时就有作者，合并时自动得到 RIS、运行清单与检索报告；
4. RIS 文件符合规范，能被文献管理软件读入。

**本轮的两个发现**：

- **以前放行、却让各来源检索不同内容的写法，现在报错**：未配对的引号（OpenAlex 会把运算符当成词，S2 收到的是另一条检索式）；逗号（以前只对 OpenAlex 报错，S2 照常检索）；括号内的词之间缺少 OR、组与组之间缺少 AND（各来源与本地判断的含义不一致）。仓库里 72 个原始结果文件记录的检索式全部仍能解析。
- **Crossref 的检索面向参考文献匹配**：教程的 v1 Q1、Q3、Q4 与 v2b Q2 各取前 40 条，本地满足检索式的都是 0 条（常见词占满前列，多数记录没有摘要）；两三个词的简单检索式能找到（如 Anderson 等 2024 的同质化研究）。因此保持默认关闭，开启前请知悉。

**阶段 3 验收**：

1. 现有输出不变：录制件回放的检索记录逐字节相同；全部示例检索式的 dry-run 输出相同；`--legacy` 照常逐字节复现；
2. 检索式错误带错误码与位置，助手据此能一次改对；
3. Crossref 作为第一个新增数据源，只新增一个模块和一份测试件，`search.py`、`merge.py` 不再为它改动；
4. 某个来源不支持某项写法时，dry-run 打印 SKIPPED 及原因，而不是悄悄改写。
